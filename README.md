ケアすてっぷ
― 妊娠・出産に伴う社内手続きをサポートするアプリ

1. サービス概要

妊娠した社員、または配偶者が妊娠した社員が、産前産後休業から育児休業、復職までに必要となる社内手続きや公的手続きについて、いつ、何を行えばよいのかを確認できる管理サービスを提供します。
社員と労務担当者が手続きの内容や進捗状況を共有することで、手続きに対する不安や負担を軽減し、社員が安心して出産・育児に向き合える環境を作ることを目的とします。

2. このアイデアはどこから生まれたか

私自身が労務担当者として、社員の妊娠・出産に伴う社内手続きや公的手続きに関わってきた経験から生まれたアイデアです。
産休・育休に関する手続きは、社員にとって初めて経験するものが多く、また手続きの種類も多いため、「いつ、何をすればよいのか」が分かりにくい場合があります。
労務担当者側から見ても、社員とのやり取りや手続きの進捗状況を管理する必要があります。
そこで、妊娠・出産という一つのライフイベントに焦点を当て、社員と労務担当者の双方が手続きを分かりやすく管理できるサービスを考えました。

が分かりにくい。

3-2. 本当に解決したい課題は何か

妊娠・出産に伴う手続きは、社員にとって初めて経験するものが多く、必要な手続きや期限が分からないことが不安や負担につながっています。
また、労務担当者側も、社員とのやり取りや複数の手続きの進捗状況を管理する必要があります。
そこで、必要な情報や手続きの進捗を一元管理することで、社員と労務担当者双方の不安や負担を軽減することを課題解決の目的とします。

4-2. 実際に使われる可能性について（需要・存在確認）

妊娠・出産に伴う手続きは、対象となる社員が頻繁に経験するものではなく、初めて経験するケースが多いと考えられます。
そのため、必要な手続きや期限を分かりやすく確認でき、現在の進捗状況も一元管理できるサービスには一定の需要があると考えています。
特に、すでに給与・勤怠等のシステムを導入しているものの、妊娠・出産に関する手続きまで専用に管理できる仕組みを持っていない中小企業を想定しています。

4-3. ユーザーがサービスを導入して利用するまでのイメージ

① 妊娠発覚・会社への報告：社員
社員が妊娠したことを会社へ報告します。

② 産休から育休、復職までの流れを説明：労務担当者
報告を受けた労務担当者が、今後の手続きや産休・育休から復職までの流れを説明します。

③ 産休開始予定日の報告：社員
社員が産休開始予定日を会社へ報告します。

④ アカウント発行：労務担当者
労務担当者が、今後の手続きや情報共有に「ケアすてっぷ」を利用するため、社員のアカウントを発行します。

⑤ 必要事項の登録：社員
社員がアプリにログインし、出産予定日や産休期間などの必要事項を登録します。

⑥ 必要な手続き・書類・期限の確認：社員
登録された情報をもとに、アプリに必要な手続きや書類、提出期限などが表示されます。社員はそれらを確認し、必要書類を準備します。

⑦ 書類の提出：社員
社員が必要書類を会社へ提出します。

⑧ 手続き・進捗状況の登録：労務担当者
労務担当者が提出された書類を確認して必要な手続きを行い、アプリに手続きの進捗状況を登録します。

MVPで実装する範囲
上記①～⑧の利用フローのうち、アプリ上で必要となる④～⑧の基本機能をMVPとして実装します。
①～③は社員と会社との実際のやり取りを想定しています。
MVPでは、社員がアカウント発行後に必要事項を登録し、必要な手続き・書類・期限を確認できること、また労務担当者が手続きの進捗状況を登録・更新できることを基本的な機能とします。

5. 既存サービス・競合調査
5-1. 似たサービスの調査

本サービスは、妊娠・出産をした社員と労務担当者との間で、産休・育休から復職までに必要となる手続きや書類、期限、進捗状況を一元管理することを目的としています。
調査した範囲では、今回想定している用途に特化した公開サービスは確認できませんでした。
一方で、freee人事労務やSmartHRなどの人事・労務管理サービスには、産休・育休に関する管理・申請機能があります。
これらは企業全体の人事・労務管理を目的としたサービスであり、本サービスとは対象範囲が異なります。
また、公的機関からも妊娠・出産に伴う手続きや企業による支援に関する情報が提供されています。

5-2. それでも自分が作りたい理由

私自身が労務担当者として、社員の妊娠・出産に伴う手続きに関わってきた経験があります。
既存の人事・労務システムには産休・育休に関する機能が含まれているものもありますが、給与・勤怠・従業員管理など、企業の人事・労務業務全体を対象とした大規模なサービスが中心です。
すでに別の給与・勤怠システムを利用している企業が、産休・育休の手続きだけを目的として新たに大規模な人事・労務システムを導入することには、コストや運用面でのハードルがあると考えました。
そこで、既存のシステムを変更することなく、妊娠・出産に伴う手続きに特化して利用できる、より小規模で導入しやすいサービスを作りたいと考えました。

5-3. 差別化を「体験価値」で表現する

「ケアすてっぷ」の差別化ポイントは、手続きそのものを管理するだけではなく、社員が**「今、自分は何をすればよいのか」**を分かりやすく把握できることです。
妊娠・出産に伴う社内手続きや公的手続きについて、

必要な手続き
必要な書類
提出期限
現在の進捗状況

を一元的に確認できるようにすることで、手続きに対する不安や負担を軽減します。
また、社員だけでなく労務担当者も進捗状況を確認できるようにすることで、双方の情報共有をスムーズにします。

6. このサービスで提供したい価値
6-1. ユーザーの変化

妊娠・出産に伴う手続きについて、「何をすればいいのか分からない」という状態から、「次に何をすればいいのか分かる」状態へ変えることを目指します。
その結果、社員が手続きに過度に振り回されることなく、安心して出産・育児に向き合える環境を提供します。

6-2. 価値を一文で表す

「ケアすてっぷ」は、妊娠・出産に伴う手続きを分かりやすく整理し、社員が安心して次のステップへ進めるようサポートするサービスです。

8. このアプリの懸念点とその対策
懸念点①
何が問題になりそうか
手続きが複雑なため、アプリ自体が複雑になってしまう可能性があります。

なぜそう思うか
産休・育休に関する手続きは、社員の状況や会社の制度などによって必要な対応が異なり、すべてのケースに対応しようとすると、必要な機能が増えてしまうためです。

そのために考えている対策
MVPでは基本的なケースに対象を限定します。
例外的なケースについては無理にシステムで対応せず、労務担当者による個別対応とします。
まずは「必要な手続き・期限・進捗を確認できる」という基本的な価値を実現することを優先します。

懸念点②
何が問題になりそうか
行政の手続きや書類は、法改正などによって年度ごとに変更される可能性があります。

なぜそう思うか
「ケアすてっぷ」では、必要な手続きや書類、期限をユーザーに表示するため、情報が変更された場合には、アプリ内の情報も更新する必要があります。

そのために考えている対策
MVPでは対象とする基本的な手続きに限定し、手続きや書類の情報をアプリ内で管理できる構成とします。
将来的には、労務担当者が必要な情報を更新できる仕組みを検討します。

10-2. 技術選定の比較検討

本アプリの開発にあたり、複数の技術について検討しました。
現在、Ruby on Railsを中心に、ReactやNext.jsなどについても学習しています。
ReactやNext.jsについてはフロントエンドを中心に学習しており、フロントエンドの実装については一定の知識があります。
一方で、バックエンド、データベース、認証、サーバーサイドの処理などを含めたWebアプリケーション全体を構築するという点では、現時点ではRuby on Railsのほうが、自分の知識・経験を活用して開発しやすいと判断しました。
また、本アプリは11月5日までにMVPを完成させる必要があるため、技術の習得そのものに時間をかけるよりも、既に学習している技術を活用して開発を進めることを優先します。
以上の理由から、今回はRuby on Railsを採用します。

候補	採用/不採用	理由
Ruby on Rails	採用	現在、中心的に学習しており、バックエンドを含めたWebアプリケーション開発に活用できるため
React	不採用	フロントエンドについては学習しているが、今回必要となるアプリケーション全体を構築するには追加の学習が必要となるため
Next.js	不採用	フロントエンドを含めた知識はあるものの、現時点ではRailsのほうが既存の知識を活用して開発しやすいため

今回チャレンジしたい点
Railsを使用して、一つのWebアプリケーションを完成させる
社員側と労務担当者側という異なる権限を持つユーザーを扱う
手続き・期限・進捗状況をデータベースで管理する
実際の業務を想定したデータ構造・画面設計を行う

不安な点
Railsについて学習を進めているものの、実際に一からアプリケーションを設計・開発した経験は十分ではありません。
そのため、実装中に理解不足や技術的な問題が発生する可能性があります。

10-3. キャッチアップ不足の懸念

現在、ReactやNext.jsについても学習していますが、主にフロントエンドを中心とした学習となっています。
Webアプリケーションを完成させるためには、フロントエンドだけでなく、バックエンド、データベース、認証、サーバーサイドの処理など、幅広い知識が必要となります。
新しい技術を採用してこれらを同時にキャッチアップすると、学習そのものに時間がかかり、MVPの完成に影響する可能性があります。
そのため今回は、これまで学習してきたRuby on Railsを中心に開発し、新しい技術の習得よりもMVPを期限内に完成させることを優先します。
また、実装中に問題が発生した場合は、公式ドキュメント、学習教材、検索、AIなどを活用して解決を図ります。
ReactやNext.jsなどの技術については、MVP完成後に必要性を検討し、今後の機能拡張の際に導入を検討します。
